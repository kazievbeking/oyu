# ОЮ — HTML-версия для GitHub Pages

Сохранены оформление и структура сайта:

- `index.html` — главная с четырьмя разделами;
- `section.html?id=animals` — страница раздела с его ою и поиском;
- `ornament.html?id=…` — полная информация об ою;
- `admin.html` — админка с обзором, разделами, списком ою и отдельными редакторами.

Основной язык — казахский. Переключение **ҚАЗ / РУС / ENG** работает на всех страницах и в админке. Сборка и PHP не нужны. Все ссылки относительные: сайт работает и в корне домена, и по адресу `username.github.io/repository/`.

## Описание на трёх языках

В редакторе ою есть вкладки **Қазақша**, **Русский** и **English**. Описание обязательно на всех трёх языках. Краткое название, история, значение и применение также имеют отдельные поля для каждого языка. Название ою на казахском общее для трёх версий. Для разделов добавлены английские название и описание. Существующие записи без перевода временно показывают казахский текст; автоматического машинного перевода введённого текста нет.

## Кнопка «Загрузить в GitHub»

Подключён репозиторий **https://github.com/kazievbeking/oyu**, ветка по умолчанию — `main`. Сначала сохраните форму, затем нажмите «GitHub-қа жүктеу / Загрузить в GitHub / Upload to GitHub».

1. Создайте fine-grained personal access token в GitHub: Settings → Developer settings → Personal access tokens → Fine-grained tokens.
2. Выберите **Only select repositories → oyu** и **Repository permissions → Contents → Read and write**. Другие права не требуются.
3. Введите токен в диалоге админки и нажмите «Загрузить». Не помещайте токен в исходники, JSON или чат.
4. В пустой репозиторий первая загрузка добавит весь сайт. В дальнейшем каталог и изображения обновляются одной записью-коммитом: `data/catalog.json` и `assets/catalog.js`. Изображения встроены в JSON.
5. Один раз включите публикацию сайта в https://github.com/kazievbeking/oyu/settings/pages: Deploy from a branch → `main` → `/ (root)`. Кнопка загружает файлы, но не меняет настройки Pages. Обновление публичного сайта происходит после сборки GitHub Pages.

Для отправки используйте сайт по HTTP/HTTPS, например через Live Server или GitHub Pages. При `file://` отправка заблокирована. Токен существует только в поле пароля и временно в памяти запроса, не сохраняется в браузерное хранилище и очищается после попытки загрузки. Требуется токен при каждой отправке. Проверка конфликтов останавливает отправку, если опубликованный каталог был изменён другим редактором. При конфликте сначала экспортируйте локальную версию; после обновления GitHub Pages сбросьте локальные изменения, объедините свою копию с актуальным JSON и импортируйте результат. Принудительная перезапись ветки не используется.

Техническая документация: [GitHub Git database API](https://docs.github.com/en/rest/git), [права Contents API](https://docs.github.com/en/rest/repos/contents).

## Загрузка на GitHub

1. Распакуйте архив `oyu-github-pages.zip` и загрузите его содержимое в корень репозитория.
2. В настройках репозитория откройте Pages, выберите публикацию из своей ветки и корневой папки.
3. Начальная страница — `index.html`.

Для загрузки вручную достаточно четырёх HTML-файлов, папок `assets`, `data`, `uploads` и файла `.nojekyll`. Документы и старые ZIP-архивы из рабочей папки в сайт не включены.

## Админка на статическом сайте

Пароль для входа в локальный редактор: `Admin`.

GitHub Pages не исполняет серверный код. Экран входа служит только переключателем интерфейса и **не защищает данные на сервере**. Не размещайте в каталоге секреты. В публичном JSON нет хеша старого серверного пароля и счётчиков входа.

Редактор сохраняет изменения и изображения в IndexedDB текущего браузера. Они сразу видны в этом же браузере; другие посетители увидят их после отправки в GitHub и обновления Pages. Экспорт архива остаётся запасным способом публикации.

Для публикации изменений:

1. Измените данные в админке и сохраните.
2. Нажмите «GitHub үшін архив жүктеу / Скачать архив для GitHub».
3. Распакуйте полученный `oyu-catalog-github.zip` поверх репозитория. Он содержит `data/catalog.json` и `assets/catalog.js`.
4. Загрузите изменения в GitHub. Обновляйте оба файла одновременно.

Загруженные через редактор JPG/PNG/WebP встраиваются в JSON, поэтому их не нужно переносить отдельно. Максимум 5 МБ на изображение. Используйте сжатые изображения для быстрой загрузки. Кнопка импорта принимает `catalog.json`. Кнопка сброса удаляет только локальные изменения и возвращает опубликованную версию.

## Локальный просмотр

Можно открыть `index.html` непосредственно в современном браузере. Резервный `assets/catalog.js` позволяет читать данные без `fetch` при запуске через `file://`. Для проверки работы как на хостинге лучше использовать любой статический HTTP-сервер или Live Server.

Google Fonts требует подключения к интернету; при его отсутствии используются системные шрифты. Исходные SVG-обложки разделов находятся в `assets/sections/`.

Начальная коллекция содержит только четыре раздела, без ою. Неизвестный идентификатор показывает экран «Не найдено» внутри HTML-страницы; HTTP-статус на GitHub Pages остаётся 200, поскольку обработка выполняется в браузере.
